<h1 style="font-size:29px;line-height:1.25;margin:14px 0 6px;">Cpk vs Ppk: the only real difference is which standard deviation you use</h1>
<p style="color:#5b6675;font-size:15px;margin:0 0 6px;">Same mean, same specification limits, different sigma. Here is what that gap is telling you about your process.</p>
<p style="color:#8a94a3;font-size:12px;margin:0 0 16px;">Updated 13 November 2026 · 7 min read · Written for working labs and quality teams</p>
<div style="background:#eef4ff;border-left:4px solid #1e4d8b;border-radius:8px;padding:14px 18px;margin:0 0 22px;"><p style="margin:0 0 6px;font-size:11px;font-weight:700;letter-spacing:.6px;color:#1e4d8b;text-transform:uppercase;">Short answer</p><p style="margin:0;font-size:15px;">Cpk and Ppk use the same limits and the same mean — the difference is the standard deviation. <b>Cpk</b> uses within-subgroup variation (estimated from R̄/d2 or s̄/c4), i.e. short-term, common-cause noise. <b>Ppk</b> uses the overall sample standard deviation of all the data, which also contains between-subgroup drift. When a process is stable the two numbers are close; a large gap is not a calculation error, it is a signal that the process moved while you were collecting data.</p></div>
<div style="border:1px solid #e6e9ef;border-radius:8px;padding:12px 16px;margin:0 0 24px;"><p style="margin:0 0 6px;font-size:12px;font-weight:700;color:#5b6675;">On this page</p><ol style="margin:0;padding-left:20px;font-size:13.5px;"><li><a href="#s1" style="color:#2563eb;">The two formulas side by side</a></li><li><a href="#s2" style="color:#2563eb;">A worked example with real numbers</a></li><li><a href="#s3" style="color:#2563eb;">When to report which one</a></li><li><a href="#s4" style="color:#2563eb;">Four checks before you calculate anything</a></li><li><a href="#where-it-goes-wrong" style="color:#2563eb;">Where this goes wrong in practice</a></li><li><a href="#faq" style="color:#2563eb;">Frequently asked</a></li></ol></div>
<h2 id="s1" style="font-size:20px;margin-top:30px;margin-bottom:8px;">The two formulas side by side</h2>
<p style="margin:0 0 12px;">Both indices compare the distance from the process mean to the nearest specification limit against three sigmas. The only thing that changes is the sigma:</p>
<div style="overflow-x:auto;margin:0 0 16px;"><table style="width:100%;border-collapse:collapse;font-size:13.5px;"><thead><tr><th style="border:1px solid #e6e9ef;padding:8px 10px;text-align:left;background:#f3f6fb;">Index</th><th style="border:1px solid #e6e9ef;padding:8px 10px;text-align:left;background:#f3f6fb;">Sigma used</th><th style="border:1px solid #e6e9ef;padding:8px 10px;text-align:left;background:#f3f6fb;">What it answers</th></tr></thead><tbody><tr><td style="border:1px solid #e6e9ef;padding:8px 10px;vertical-align:top;">Cp = (USL − LSL) / 6σ<sub>within</sub></td><td style="border:1px solid #e6e9ef;padding:8px 10px;vertical-align:top;">Within-subgroup</td><td style="border:1px solid #e6e9ef;padding:8px 10px;vertical-align:top;">Could this process fit, if centred?</td></tr><tr><td style="border:1px solid #e6e9ef;padding:8px 10px;vertical-align:top;">Cpk = min[(USL − μ), (μ − LSL)] / 3σ<sub>within</sub></td><td style="border:1px solid #e6e9ef;padding:8px 10px;vertical-align:top;">Within-subgroup</td><td style="border:1px solid #e6e9ef;padding:8px 10px;vertical-align:top;">Could it fit, as it is actually centred?</td></tr><tr><td style="border:1px solid #e6e9ef;padding:8px 10px;vertical-align:top;">Pp = (USL − LSL) / 6s<sub>overall</sub></td><td style="border:1px solid #e6e9ef;padding:8px 10px;vertical-align:top;">Overall sample s</td><td style="border:1px solid #e6e9ef;padding:8px 10px;vertical-align:top;">Did the whole run fit?</td></tr><tr><td style="border:1px solid #e6e9ef;padding:8px 10px;vertical-align:top;">Ppk = min[(USL − μ), (μ − LSL)] / 3s<sub>overall</sub></td><td style="border:1px solid #e6e9ef;padding:8px 10px;vertical-align:top;">Overall sample s</td><td style="border:1px solid #e6e9ef;padding:8px 10px;vertical-align:top;">Did the whole run fit, as centred?</td></tr></tbody></table></div>
<p style="background:#fff8e8;border:1px solid #f0d9a0;border-radius:8px;padding:11px 15px;margin:0 0 16px;font-size:14px;"><b>Practical note.</b> Cp and Pp ignore centering entirely — a process sitting right on the upper limit can still show a beautiful Cp. Always read the index together with the mean and the histogram, never as a standalone pass mark.</p>
<h2 id="s2" style="font-size:20px;margin-top:30px;margin-bottom:8px;">A worked example with real numbers</h2>
<p style="margin:0 0 12px;">A turned shaft is specified at 10.00 ± 0.20 mm, so LSL = 9.80 and USL = 10.20. You collect 25 subgroups of 5. The grand mean μ = 10.02, the within-subgroup sigma from R̄/d2 is 0.030, and the overall standard deviation of all 125 values is 0.055.</p>
<p style="margin:0 0 12px;"><b>Cpk</b> = min[(10.20 − 10.02) / (3 × 0.030), (10.02 − 9.80) / (3 × 0.030)] = min[2.00, 2.44] = <b>2.00</b>.</p>
<p style="margin:0 0 12px;"><b>Ppk</b> = min[(10.20 − 10.02) / (3 × 0.055), (10.02 − 9.80) / (3 × 0.055)] = min[1.09, 1.33] = <b>1.09</b>.</p>
<p style="margin:0 0 12px;">Nothing is wrong with the arithmetic. The process is capable in the short term (2.00) but the overall performance is only 1.09, because subgroup means wandered — tool wear, a shift change, a warm-up drift, or two batches of material. Reporting only the 2.00 would be the mistake.</p>
<h2 id="s3" style="font-size:20px;margin-top:30px;margin-bottom:8px;">When to report which one</h2>
<ul style="margin:0 0 14px;padding-left:22px;"><li style="margin-bottom:7px;"><b>Initial submission / PPAP:</b> customers commonly ask for Ppk ≥ 1.67 from the initial run, because it reflects everything that actually happened. This is a customer or AIAG PPAP convention, not an ISO 9001 or IATF 16949 clause requirement.</li><li style="margin-bottom:7px;"><b>Series production monitoring:</b> Cpk ≥ 1.33 is the most common contractual target, again a customer requirement rather than a line in the standard.</li><li style="margin-bottom:7px;"><b>Both together:</b> the gap itself is the diagnostic. If Cpk ≈ Ppk, common-cause variation dominates and the process is behaving predictably. If Cpk is much larger, hunt for special causes between subgroups before quoting any capability number.</li><li style="margin-bottom:7px;"><b>Neither:</b> if the process is not stable, or the data are strongly non-normal, a capability index is a number without a model behind it. Stabilise first, or use a transformation / non-normal method and say which one you used.</li></ul>
<h2 id="s4" style="font-size:20px;margin-top:30px;margin-bottom:8px;">Four checks before you calculate anything</h2>
<ol style="margin:0 0 14px;padding-left:22px;"><li style="margin-bottom:9px;"><b>Measurement system first.</b> If the gage R&amp;R is poor relative to the tolerance, the spread you are measuring belongs partly to the gage, not the process.</li><li style="margin-bottom:9px;"><b>Rational subgroups.</b> Put parts made under the same conditions in one subgroup; otherwise within-subgroup sigma is contaminated by exactly the drift you are trying to detect.</li><li style="margin-bottom:9px;"><b>Enough data.</b> A Cpk from 8 values is a point estimate with a very wide confidence interval. The commonly used floor is roughly 25 subgroups / 100 values, and the estimate should be reported with its uncertainty if a decision hinges on it.</li><li style="margin-bottom:9px;"><b>Right chart, right limits.</b> Control limits come from process data; specification limits come from the customer. Drawing a spec line on an X̄ chart as if it were a control limit is the single most common shop-floor error.</li></ol>
<h2 id="where-it-goes-wrong" style="font-size:20px;margin-top:30px;margin-bottom:8px;">Where this goes wrong in practice</h2>
<p style="margin:0 0 11px;">Computing Cpk with the overall sample standard deviation. You get Ppk twice and lose the only signal that separates short-term capability from long-term drift.</p>
<p style="margin:0 0 11px;">Quoting Cpk on an unstable process. An index assumes a stable, predictable distribution; an out-of-control chart invalidates the premise, not just the number.</p>
<p style="margin:0 0 11px;">Treating 1.33 as law. It is a widespread customer target. Check the contract, the control plan and the customer-specific requirements before you set an acceptance threshold.</p>
<p style="margin:0 0 11px;">Averaging Cpk values across shifts or cavities instead of looking at each stream separately — two healthy streams straddling the mean can hide a bimodal mess.</p>
<h2 id="faq" style="font-size:20px;margin-top:30px;margin-bottom:8px;">Frequently asked</h2>
<p style="margin:0 0 10px;"><b>Is Cpk always higher than Ppk?</b><br>Usually, because overall variation includes within-subgroup variation plus any between-subgroup movement. But it is not a mathematical guarantee: with unusual subgroup patterns the overall estimate can be smaller than the within estimate. Treat the gap as a diagnostic, not a rule.</p>
<p style="margin:0 0 10px;"><b>What is a good Cpk value?</b><br>It depends on the contract and the risk. 1.33 is the most common series-production target and 1.67 is often requested for initial or safety-related characteristics; neither appears as a number in ISO 9001 or IATF 16949. For safety or regulated characteristics, the customer-specific requirements govern.</p>
<p style="margin:0 0 10px;"><b>Can Cpk be negative?</b><br>Yes. If the process mean has moved outside a specification limit, the distance to that limit is negative, so the minimum becomes negative. It means the process is producing out-of-spec material at the centre of its distribution, not merely in a tail.</p>
<p style="margin:0 0 10px;"><b>Do I need both Cpk and Ppk for a submission?</b><br>Most automotive customers ask for the initial-process performance index (Ppk) from the submission run and capability (Cpk) once the process is stable. Check the submission level and customer-specific requirements — the required index and minimum are contractual, not universal.</p>
