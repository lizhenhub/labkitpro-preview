<h1 style="font-size:29px;line-height:1.25;margin:14px 0 6px;">How to write an 8D report a customer will actually accept</h1>
<p style="color:#5b6675;font-size:15px;margin:0 0 6px;">Most 8Ds get rejected at D4 — not because of formatting, but because the root cause is a person's name.</p>
<p style="color:#8a94a3;font-size:12px;margin:0 0 16px;">Updated 13 November 2026 · 8 min read · Written for working labs and quality teams</p>
<div style="background:#eef4ff;border-left:4px solid #1e4d8b;border-radius:8px;padding:14px 18px;margin:0 0 22px;"><p style="margin:0 0 6px;font-size:11px;font-weight:700;letter-spacing:.6px;color:#1e4d8b;text-transform:uppercase;">Short answer</p><p style="margin:0;font-size:15px;">An acceptable 8D proves four things: the problem is quantified (D2), all affected material is contained with traceable quantities (D3), the <b>occurrence cause</b> and the <b>escape cause</b> are separately established and evidenced (D4), and the permanent actions are verified and propagated into the PFMEA, control plan and work instructions (D5–D7). Most rejections happen at D4, where "operator error / retraining" is offered as a root cause instead of a system weakness that allowed the error.</p></div>
<div style="border:1px solid #e6e9ef;border-radius:8px;padding:12px 16px;margin:0 0 24px;"><p style="margin:0 0 6px;font-size:12px;font-weight:700;color:#5b6675;">On this page</p><ol style="margin:0;padding-left:20px;font-size:13.5px;"><li><a href="#s1" style="color:#2563eb;">D0 to D8, with what the customer checks</a></li><li><a href="#s2" style="color:#2563eb;">The two causes you must separate</a></li><li><a href="#s3" style="color:#2563eb;">Containment is a quantity, not a sentence</a></li><li><a href="#s4" style="color:#2563eb;">D7 is where the 8D pays for itself</a></li><li><a href="#where-it-goes-wrong" style="color:#2563eb;">Where this goes wrong in practice</a></li><li><a href="#faq" style="color:#2563eb;">Frequently asked</a></li></ol></div>
<h2 id="s1" style="font-size:20px;margin-top:30px;margin-bottom:8px;">D0 to D8, with what the customer checks</h2>

<h2 id="s2" style="font-size:20px;margin-top:30px;margin-bottom:8px;">The two causes you must separate</h2>
<p style="margin:0 0 12px;"><b>Occurrence cause</b>: why the defect was made. <b>Escape cause</b>: why the existing controls did not catch it before shipment. A missing clip because the fixture wore out is an occurrence cause; the fact that the end-of-line check does not verify clip presence is an escape cause. An 8D with only one cause is normally returned, because fixing one leaves the other route open.</p>
<p style="margin:0 0 12px;">For each cause, run a 5-Why chain and stop only at a level where a controllable system element appears — maintenance interval, error-proofing, inspection method definition, supplier change control. Then verify the chain with evidence: the worn fixture's measurement, the work instruction that lacks the check, the audit record that never covered it. A 5-Why chain with no attachments is a story, not an analysis.</p>
<p style="background:#fff8e8;border:1px solid #f0d9a0;border-radius:8px;padding:11px 15px;margin:0 0 16px;font-size:14px;"><b>Practical note.</b> "Operator error" is not a root cause; it is the last visible link in a chain. Ask why the method allowed the error: no poka-yoke, ambiguous instruction, rushed cycle time, inadequate training verification, or a temporary worker on an unqualified station. Fixing the system element closes the chain; retraining alone leaves it exactly as it was.</p>
<h2 id="s3" style="font-size:20px;margin-top:30px;margin-bottom:8px;">Containment is a quantity, not a sentence</h2>
<ul style="margin:0 0 14px;padding-left:22px;"><li style="margin-bottom:7px;">List every population: finished goods, WIP, in transit, customer stock, returned parts, and parts already assembled into higher-level products.</li><li style="margin-bottom:7px;">For each, state the quantity, the sort method, the number of defects found, the date/time, and who did it. Reconcile the numbers so they add up to the shipped quantity in D2.</li><li style="margin-bottom:7px;">Identify the containment with a traceable mark or label so an auditor can tell sorted from unsorted stock three months later.</li><li style="margin-bottom:7px;">Verify the containment itself (e.g. re-check a sample of the sorted lot) and only remove it after D6 validation data shows the PCA works.</li></ul>
<h2 id="s4" style="font-size:20px;margin-top:30px;margin-bottom:8px;">D7 is where the 8D pays for itself</h2>
<p style="margin:0 0 12px;">Once the PCA is validated, update the PFMEA (new prevention/detection control, re-scored S/O/D and Action Priority), the control plan (control method, sample size, frequency, reaction plan), the work instruction and the training/qualification records. Then perform read-across: which other part numbers, lines or suppliers share the same failure mode? A customer asking "why did this happen again on another line six months later" is asking about D7, not D4.</p>
<p style="margin:0 0 12px;">Keep the evidence pack together — problem description, containment records, cause-analysis data, validation results, updated documents with revision numbers, and closure approval. An 8D that cannot be reconstructed from its attachments will not survive a subsequent customer or certification audit.</p>
<h2 id="where-it-goes-wrong" style="font-size:20px;margin-top:30px;margin-bottom:8px;">Where this goes wrong in practice</h2>
<p style="margin:0 0 11px;">Naming "operator error", "lack of awareness" or "human mistake" as the root cause and closing with retraining.</p>
<p style="margin:0 0 11px;">Writing D3 as "all stock checked" with no quantities, no reconciliation and no way to prove which stock was checked.</p>
<p style="margin:0 0 11px;">Skipping the escape cause entirely, so the same defect can ship again undetected.</p>
<p style="margin:0 0 11px;">Choosing a PCA before the root cause is confirmed, and never validating whether it reduced the defect rate.</p>
<p style="margin:0 0 11px;">Leaving the PFMEA, control plan and work instructions untouched at D7 — then treating the next occurrence as a brand-new problem.</p>
<h2 id="faq" style="font-size:20px;margin-top:30px;margin-bottom:8px;">Frequently asked</h2>
<p style="margin:0 0 10px;"><b>Is 8D required by ISO 9001 or IATF 16949?</b><br>No — 8D is a customer-driven problem-solving method, widely required through automotive customer-specific requirements. The standards require corrective actions, root-cause analysis, evaluation of effectiveness and updates to the QMS; 8D is one structured way to document that work.</p>
<p style="margin:0 0 10px;"><b>What is the difference between D3 containment and D5 permanent action?</b><br>D3 is a temporary measure that protects the customer immediately (sorting, extra inspection, quarantine); it does not change the process. D5 changes the process so the cause cannot recur. D6 removes the temporary measure only after the permanent one has been validated with data.</p>
<p style="margin:0 0 10px;"><b>How long should an 8D take?</b><br>Customers usually set their own cadence — often an initial response within 24 hours, containment evidence within a few days, and a final 8D within 10–30 days. Ask for the customer's specific timing requirement in their supplier manual rather than assuming a fixed number.</p>
<p style="margin:0 0 10px;"><b>Do I need both a 5-Why and a fishbone diagram?</b><br>No method is mandated. What matters is that the analysis separates occurrence from escape, is supported by evidence, and reaches a controllable system cause. Many teams use a fishbone to structure candidate causes and 5-Why to drill down on the confirmed ones.</p>
