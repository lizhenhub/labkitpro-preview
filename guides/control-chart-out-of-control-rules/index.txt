<h1 style="font-size:29px;line-height:1.25;margin:14px 0 6px;">The 8 control-chart out-of-control rules — and when enabling all of them is a mistake</h1>
<p style="color:#5b6675;font-size:15px;margin:0 0 6px;">Nelson / Western Electric patterns, what each one detects, and the false-alarm cost nobody mentions.</p>
<p style="color:#8a94a3;font-size:12px;margin:0 0 16px;">Updated 13 November 2026 · 7 min read · Written for working labs and quality teams</p>
<div style="background:#eef4ff;border-left:4px solid #1e4d8b;border-radius:8px;padding:14px 18px;margin:0 0 22px;"><p style="margin:0 0 6px;font-size:11px;font-weight:700;letter-spacing:.6px;color:#1e4d8b;text-transform:uppercase;">Short answer</p><p style="margin:0;font-size:15px;">The eight commonly used run rules flag non-random patterns beyond a single point outside 3σ: 1 point beyond 3σ; 9 points on one side of the centre line; 6 steadily increasing or decreasing; 14 alternating up and down; 2 of 3 beyond 2σ; 4 of 5 beyond 1σ; 15 points within 1σ of the centre line; and 8 points with none within 1σ. Each detects a different assignable cause — but enabling all eight on every chart raises false alarms sharply, so choose the rule set per process and document it.</p></div>

Numbering and exact counts vary slightly between software packages and AIAG/SPC references — write down the rule set you actually use in the control-plan or procedure, and keep it consistent across shifts. The pattern logic matters more than the numbering.</p>

<h2 id="s2" style="font-size:20px;margin-top:30px;margin-bottom:8px;">Reading rules 7 and 8 correctly</h2>
<p style="margin:0 0 12px;">Rules 7 and 8 are counter-intuitive and are where practical experience shows up. Rule 7 looks like "wonderfully tight control", but fifteen points hugging the centre line usually means the data are rounded too coarsely, the gage resolution is inadequate, or someone is averaging across streams before plotting. Rule 8 looks like "wild variation", yet it is often two perfectly stable streams — two cavities, two spindles, two suppliers — plotted on one chart. Splitting the chart by stream resolves it; tightening the process does not.</p>
<p style="margin:0 0 12px;">Rule 4 (alternating) is the signature of operator over-adjustment: every time the chart moves, someone nudges the setpoint. The fix is to stop adjusting to common-cause noise, not to narrow the control limits.</p>
<h2 id="s3" style="font-size:20px;margin-top:30px;margin-bottom:8px;">Choosing which rules to enable</h2>
<ul style="margin:0 0 14px;padding-left:22px;"><li style="margin-bottom:7px;"><b>Rule 1 alone</b> has a false-alarm probability of about 0.27% per point for a stable normal process. Adding rules 2, 5 and 6 increases sensitivity to small shifts — and also increases the total false-alarm rate. More sensitivity is not free.</li><li style="margin-bottom:7px;"><b>High-volume, low-consequence processes:</b> rule 1 plus rule 2 is often enough; add 5/6 when a small shift is expensive to miss.</li><li style="margin-bottom:7px;"><b>Safety or regulated characteristics:</b> enable the documented rule set the customer requires, and make sure the reaction plan says what to do for each signal.</li><li style="margin-bottom:7px;"><b>Always pair a rule with a reaction plan.</b> A signal with no defined response — contain, check the last good point, investigate, record — is just a red dot on a screen.</li></ul>
<p style="background:#fff8e8;border:1px solid #f0d9a0;border-radius:8px;padding:11px 15px;margin:0 0 16px;font-size:14px;"><b>Practical note.</b> Control limits are calculated from process data; specification limits come from the customer and describe what the product must do. Never draw a spec line on an X̄ chart as a control limit, and never recalculate limits from a period you already know contained a special cause.</p>
<h2 id="s4" style="font-size:20px;margin-top:30px;margin-bottom:8px;">Before the first point goes on the chart</h2>
<ol style="margin:0 0 14px;padding-left:22px;"><li style="margin-bottom:9px;"><b>Rational subgrouping.</b> Sample so that within-subgroup variation represents common-cause noise only. Five consecutive parts from one setup is a subgroup; five parts spread across a shift is not.</li><li style="margin-bottom:9px;"><b>Measurement system check.</b> A poor gage R&amp;R inflates the limits and hides real signals, or creates apparent ones.</li><li style="margin-bottom:9px;"><b>Phase I vs Phase II.</b> Use an initial baseline run to estimate limits with known special causes removed; then freeze those limits for monitoring. Quietly re-fitting limits every week makes the chart unable to detect drift.</li><li style="margin-bottom:9px;"><b>Chart type matches the data.</b> X̄-R / X̄-s for subgrouped variable data, I-MR for individual measurements, p / np for pass-fail proportions, c / u for counts. Capability analysis comes after stability, not before.</li></ol>
<h2 id="where-it-goes-wrong" style="font-size:20px;margin-top:30px;margin-bottom:8px;">Where this goes wrong in practice</h2>
<p style="margin:0 0 11px;">Enabling all eight rules on every chart and then ignoring the alerts. Alarm fatigue is worse than a slightly less sensitive chart.</p>
<p style="margin:0 0 11px;">Using specification limits as control limits, which makes an incapable process look "in control" and vice versa.</p>
<p style="margin:0 0 11px;">Pooling two machines or cavities into one chart and then investigating rule 8 as if it were instability.</p>
<p style="margin:0 0 11px;">Recalculating control limits after every batch, which slowly bakes drift into the baseline.</p>
<p style="margin:0 0 11px;">Investigating a rule-1 signal without first checking whether the value was transcribed correctly — a surprising share of "special causes" are transcription errors.</p>
<h2 id="faq" style="font-size:20px;margin-top:30px;margin-bottom:8px;">Frequently asked</h2>
<p style="margin:0 0 10px;"><b>Are these rules required by ISO 9001 or IATF 16949?</b><br>No. The standards expect you to monitor and control processes and to react to special causes; the specific run-rule set is normally defined by the customer, the AIAG SPC reference manual, or your own control plan. Document which set you use.</p>
<p style="margin:0 0 10px;"><b>What is the difference between a control limit and a specification limit?</b><br>A control limit describes what the process is actually doing (calculated from process data), while a specification limit describes what the customer requires. A process can be stable and incapable, or capable on average and unstable — the two answers come from different charts.</p>
<p style="margin:0 0 10px;"><b>How many points do I need before control limits are trustworthy?</b><br>Common practice is roughly 20–25 subgroups (about 100 individual values) for a Phase I baseline, with known special causes investigated and removed before the limits are frozen. Fewer than that gives wide, unstable estimates.</p>
<p style="margin:0 0 10px;"><b>Can I use run rules on an I-MR chart with individual measurements?</b><br>Yes, most software applies rules 1–4 and 6 to individuals charts, but rules involving subgroup averages have different behaviour and autocorrelation in continuous-process data can generate false signals. Check the rule definitions in your software before applying them.</p>
