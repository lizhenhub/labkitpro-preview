<h1 style="font-size:29px;line-height:1.25;margin:14px 0 6px;">ISO 45001 的事件调查，不是一份事故报告</h1>
<p style="color:#5b6675;font-size:15px;margin:0 0 6px;">条款 10.2 要的是一条链：及时应对、调查、找到体系层根因、重评风险、实施措施、验证有效性、沟通结果。多数单位停在第二步。</p>
<p style="color:#8a94a3;font-size:12px;margin:0 0 16px;">更新于 2026 年 11 月 13 日 · 约 8 分钟 · 写给一线实验室与质量团队</p>
<div style="background:#eef4ff;border-left:4px solid #1e4d8b;border-radius:8px;padding:14px 18px;margin:0 0 22px;"><p style="margin:0 0 6px;font-size:11px;font-weight:700;letter-spacing:.6px;color:#1e4d8b;text-transform:uppercase;">短答案</p><p style="margin:0;font-size:15px;"><b>条款 10.2 的正式名称是「事件、不符合和纠正措施」</b>——「事件」写进了条款标题，所以这不是从质量体系借来的一张表。它要求建立并保持一个过程：报告与调查事件，及时应对并提供急救，通过根本原因分析评价纠正措施的需求，评审现有风险评价，实施措施，评价措施有效性，并把结果与工作人员及相关方沟通。一份以「员工未遵守规程」收尾、然后归档了事的报告，至少断了其中三环。</p></div>
<div style="border:1px solid #e6e9ef;border-radius:8px;padding:12px 16px;margin:0 0 24px;"><p style="margin:0 0 6px;font-size:12px;font-weight:700;color:#5b6675;">本页目录</p><ol style="margin:0;padding-left:20px;font-size:13.5px;"><li><a href="#s1" style="color:#2563eb;">把条款 10.2 拆成一环一环看</a></li><li><a href="#s2" style="color:#2563eb;">为什么「员工未遵守规程」不是根本原因</a></li><li><a href="#s3" style="color:#2563eb;">把闭环接回 6.1.2、7.3 和 9.3</a></li><li><a href="#where-it-goes-wrong" style="color:#2563eb;">现场最容易踩的坑</a></li><li><a href="#faq" style="color:#2563eb;">常见问题</a></li></ol></div>

<p style="background:#fff8e8;border:1px solid #f0d9a0;border-radius:8px;padding:11px 15px;margin:0 0 16px;font-size:14px;"><b>实务提示。</b> 「纠正」和「纠正措施」不是一回事。隔离设备、救治伤者、封锁通道都属于纠正——处理的是眼前状况。纠正措施要消除体系层的原因，让同类事件不再发生。多数报告里只有前一半。</p>
<h2 id="s2" style="font-size:20px;margin-top:30px;margin-bottom:8px;">为什么「员工未遵守规程」不是根本原因</h2>
<p style="margin:0 0 12px;">举一个共用通道里叉车撞到行人的例子。直接原因是行人走出了划线的人行通道。如果调查到此为止，唯一能做的动作就是重新培训这位行人——而通道布置、物流路线、班次安排、送货时序都没变，同样的事件仍然写在工作场所的设计里。</p>
<p style="margin:0 0 12px;">体系层的根本原因分析要问的是「设计为什么允许它发生」：6.1.2 的危险源辨识有没有覆盖非例行活动，比如临时加单送货、检修期间的绕行？有没有覆盖全部班次、承包方与访客？8.1.2 的控制层级有没有先考虑物理隔离，再考虑标识与培训？8.1.3 的变更管理有没有接住新改的送货路线？这些答案会产出改变现场的措施，外加一份更新过的危险源登记与风险评价——这正好对应 10.2「评审现有风险评价」的要求。</p>
<p style="margin:0 0 12px;">标准不指定方法。五个为什么、鱼骨图、故障树，或者结构化的 D0 到 D8 报告都可以。要紧的是方法被一致地应用、结论能沿时间线追溯到证据，并且至少有一条措施指向体系而不是指向个人。把调查时限写进自己的程序，然后照着执行：审核员比的是你的记录和你自己定的规则，不是某个凭空编出来的法定天数。</p>
<h2 id="s3" style="font-size:20px;margin-top:30px;margin-bottom:8px;">把闭环接回 6.1.2、7.3 和 9.3</h2>
<p style="margin:0 0 12px;">以上都按现行 2018 版执行。修订版目前处于 DIS 40.60 阶段，预计 2027 年上半年发布，过渡期安排尚未公布。请把这条闭环对着 2018 版和本机构现行书面规则跑起来，不要照着尚未发布的文本重写程序文件。</p>
<ul style="margin:0 0 14px;padding-left:22px;"><li style="margin-bottom:7px;"><b>6.1.2 危险源辨识：</b>以往事件与未遂事件是明确写进条款的输入。在危险源登记里留下带日期的调查引用，并出示受影响区域重新评价后的记录，覆盖非例行活动、承包方与访客。</li><li style="margin-bottom:7px;"><b>7.3 意识：</b>工作人员要知道怎么报告事件或未遂事件，也要知道不会因此受罚。未遂上报数是这条渠道是否有效的领先指标；一份长期空白的未遂台账是发现项，不是成绩。</li><li style="margin-bottom:7px;"><b>9.3 管理评审：</b>事件趋势与监视测量结果是评审输入，工作人员的协商意见同样要进来。带趋势去，而不只是带一叠已关闭的措施，并让决议有责任人和日期。</li><li style="margin-bottom:7px;"><b>8.2 应急准备和响应：</b>如果这次事件属于 6.1.2 识别出的应急情景之一，演练或真实事件之后必须留下预案评审与修订的证据。</li></ul>
<h2 id="where-it-goes-wrong" style="font-size:20px;margin-top:30px;margin-bottom:8px;">现场最容易踩的坑</h2>
<p style="margin:0 0 11px;">调查结论停在「员工未遵守规程」，归档了事，从不追问危险源辨识、控制层级或变更管理里是什么允许了这件事发生。</p>
<p style="margin:0 0 11px;">事件之后没有回头重跑受影响区域的 6.1.2 风险评价——这是条款 10.2 审核里最常被点名的缺口。</p>
<p style="margin:0 0 11px;">把有效性验证和措施实施签在同一天，验证在逻辑上不可能成立，记录也明显是事后补的。</p>
<p style="margin:0 0 11px;">结论只留在安全部门；或者上报渠道让人担心被追责，导致现场完全没有未遂事件上报。</p>
<h2 id="faq" style="font-size:20px;margin-top:30px;margin-bottom:8px;">常见问题</h2>
<p style="margin:0 0 10px;"><b>ISO 45001 要求每一起未遂事件都做完整调查吗？</b><br>条款 10.2 要求的是对事件与不符合进行报告、调查和采取措施的过程，并没有规定每起未遂都要查到同样深度。在自己的程序里定分级准则：高潜在后果的未遂走完整根因链条，低潜在的至少要记录并纳入趋势。未遂事件同时也是 6.1.2 危险源辨识的明确输入。</p>
<p style="margin:0 0 10px;"><b>有指定的根本原因分析方法是强制的吗？</b><br>没有。条款要求通过根本原因分析来评价纠正措施的需求，没有点名任何方法。五个为什么、鱼骨图、故障树或 D0 到 D8 报告都可以。关键是一致使用、结论能沿时间线追溯，并且至少有一条措施修的是体系而不是人。</p>
<p style="margin:0 0 10px;"><b>「纠正」和「纠正措施」到底差在哪？</b><br>纠正处理眼前状况——急救、隔离设备、封锁区域、围堵泄漏。纠正措施消除底层原因以防再发，且有效性要在之后单独检查。按 10.2，两者都要有，此外还要评审现有风险评价。</p>
<p style="margin:0 0 10px;"><b>预计 2027 年的新版会改变这套做法吗？</b><br>修订版目前处于 DIS 40.60 阶段，预计 2027 年上半年发布，过渡期安排尚未公布。凡涉及新版一律用「预计」，不要当成已定。在正式发布之前，按 ISO 45001:2018 以及本认证／认可机构现行书面规则执行。</p>
