<h1 style="font-size:29px;line-height:1.25;margin:14px 0 6px;">方法验证与方法确认：条款 7.2 真正期待的是什么</h1>
<p style="color:#5b6675;font-size:15px;margin:0 0 6px;">标准方法不等于在你的实验室自动有效。这里是评审员会要的那份证据档案。</p>
<p style="color:#8a94a3;font-size:12px;margin:0 0 16px;">更新于 2026 年 11 月 13 日 · 约 8 分钟 · 写给一线实验室与质量团队</p>
<div style="background:#eef4ff;border-left:4px solid #1e4d8b;border-radius:8px;padding:14px 18px;margin:0 0 22px;"><p style="margin:0 0 6px;font-size:11px;font-weight:700;letter-spacing:.6px;color:#1e4d8b;text-transform:uppercase;">短答案</p><p style="margin:0;font-size:15px;"><b>验证</b>（7.2.1.3）是确认本实验室——用自己的人员、仪器、试剂和基质——能正确实施已发布的标准方法，并达到该方法声称的性能。<b>确认</b>（7.2.2）是用证据证明非标、自研或修改过的方法适用于预期用途，覆盖与该用途相关的各项参数。验证是「证实能做到」，确认是「证明它成立」。</p></div>
<div style="border:1px solid #e6e9ef;border-radius:8px;padding:12px 16px;margin:0 0 24px;"><p style="margin:0 0 6px;font-size:12px;font-weight:700;color:#5b6675;">本页目录</p><ol style="margin:0;padding-left:20px;font-size:13.5px;"><li><a href="#s1" style="color:#2563eb;">你的方法该走哪一条</a></li><li><a href="#s2" style="color:#2563eb;">各项参数，以及它们各自解决什么</a></li><li><a href="#s3" style="color:#2563eb;">十分钟能追溯完的迎审档案</a></li><li><a href="#where-it-goes-wrong" style="color:#2563eb;">现场最容易踩的坑</a></li><li><a href="#faq" style="color:#2563eb;">常见问题</a></li></ol></div>
<h2 id="s1" style="font-size:20px;margin-top:30px;margin-bottom:8px;">你的方法该走哪一条</h2>
<p style="margin:0 0 12px;">评审员问得最多的一句话很朴素：「拿出记录，证明你们用自己的员工和自己的设备，在实际出具报告的样品上达到了这个方法的性能。」一份方法作业指导书和一本试剂目录，不是验证记录。</p>

<h2 id="s2" style="font-size:20px;margin-top:30px;margin-bottom:8px;">各项参数，以及它们各自解决什么</h2>
<ul style="margin:0 0 14px;padding-left:22px;"><li style="margin-bottom:7px;"><b>准确度／正确度</b>——有证标准物质、加标回收或与参考方法比对；开始前先把接收准则定下来。</li><li style="margin-bottom:7px;"><b>精密度</b>——重复性，以及必要时跨天、跨人员、跨仪器的期间精密度。一个下午的平行样只能证明重复性。</li><li style="margin-bottom:7px;"><b>专属性／选择性</b>——能否把目标物与基质干扰分开？纯溶剂里做得很漂亮的确认，往往就栽在这里。</li><li style="margin-bottom:7px;"><b>线性与范围</b>——在将要出具报告的全范围上做校准，而不是只做中间那一段；记录接收准则和残差，不能只报 R²。</li><li style="margin-bottom:7px;"><b>检出限／定量限</b>——针对基质确定，并写明采用的方法（基于空白、信噪比，或由校准曲线推出）。</li><li style="margin-bottom:7px;"><b>稳健性／耐用性</b>——主动做小改动（温度、pH、试剂批号、操作人员），证明方法能容忍正常波动。</li><li style="margin-bottom:7px;"><b>测量不确定度</b>——确认数据常常提供 7.6 预算里的 A 类分量，所以要留原始数据，不只是汇总报告。</li></ul>
<p style="background:#fff8e8;border:1px solid #f0d9a0;border-radius:8px;padding:11px 15px;margin:0 0 16px;font-size:14px;"><b>实务提示。</b> 确认的是<em>针对你认可范围的方法</em>，不是抽象意义上的技术。一份在纯溶剂里线性极好的确认档案，说明不了你能否在同样的限量下报出高脂食品基质中的农残。评审员会把确认范围与基质拿来和认可范围比对——对不上就是不符合项。</p>
<h2 id="s3" style="font-size:20px;margin-top:30px;margin-bottom:8px;">十分钟能追溯完的迎审档案</h2>
<ol style="margin:0 0 14px;padding-left:22px;"><li style="margin-bottom:9px;">方法版本与来源，附一份「已核对为现行有效版本」的书面复查记录。</li><li style="margin-bottom:9px;">预期用途说明：目标物、基质、浓度／测量范围，以及服务的客户或法规要求。</li><li style="margin-bottom:9px;">在工作开始前就写好参数、接收准则和样本量的验证／确认方案。</li><li style="margin-bottom:9px;">原始数据、计算、偏差以及针对每条准则的结论，签署并注明日期。</li><li style="margin-bottom:9px;">该方法的人员能力与授权记录（6.2），以及设备与溯源状态（6.4 / 6.5）。</li><li style="margin-bottom:9px;">与不确定度预算（7.6）、日常质控／能力验证计划（7.7）的关联，证明方法持续受控。</li><li style="margin-bottom:9px;">变更控制历史：任何修改都触发一次书面再验证或再确认。</li></ol>
<h2 id="where-it-goes-wrong" style="font-size:20px;margin-top:30px;margin-bottom:8px;">现场最容易踩的坑</h2>
<p style="margin:0 0 11px;">以为「这是标准方法」就什么都不用做。7.2.1.3 仍要求验证在本实验室能够达到方法性能。</p>
<p style="margin:0 0 11px;">在干净溶剂里做确认，却针对复杂基质出具报告；或确认范围窄于认可范围。</p>
<p style="margin:0 0 11px;">看了数据之后才定接收准则；或线性只报 R²，不做残差分析。</p>
<p style="margin:0 0 11px;">把「换了个仪器型号、换了试剂批号、缩短了孵育时间」当成行政小事，从不重新验证。</p>
<p style="margin:0 0 11px;">只留汇总报告不留原始数据，导致不确定度预算里的 A 类分量无法复原。</p>
<h2 id="faq" style="font-size:20px;margin-top:30px;margin-bottom:8px;">常见问题</h2>
<p style="margin:0 0 10px;"><b>ISO/IEC 17025:2017 要求每个方法都做确认吗？</b><br>不要求。它要求标准方法使用前做验证（7.2.1.3），对非标、自研和修改过的方法做确认（7.2.2）。两种情形下的深度都应适合预期用途，且必须保留记录。</p>
<p style="margin:0 0 10px;"><b>检测实验室里的「验证」和「校准验证」是一回事吗？</b><br>不是。这里说的验证是确认本实验室能正确运行指定方法并达到其性能；它既不同于仪器的计量「校准验证」，也不同于客户对产品的「验证」。在程序文件里把三者区分开。</p>
<p style="margin:0 0 10px;"><b>确认研究需要多少次重复？</b><br>没有通用数字。方案应由预期用途、变异性和接收准则来论证，常见做法是跨多天、多人员、多浓度水平，以便估计期间精密度。行业指南或方法本身可能规定设计。</p>
<p style="margin:0 0 10px;"><b>什么时候必须重新确认？</b><br>方法被修改、扩展到新基质或新范围、迁移到差异较大的设备，或质控／能力验证数据表明性能已变化时。把触发条件写进变更控制程序，不要依赖固定日历。</p>
